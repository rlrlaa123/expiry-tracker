# 환경 셋팅 지시서 — 유통기한 트래커 개발 준비

> 목적: 모바일(Claude 앱)에서 지시 → PC의 Claude Code가 개발 → 폰에서 핫리로드로 확인하는 무인 개발 루프 구축.
> 소요: 약 1~2시간 (dev build 클라우드 빌드 대기 포함)
> 전제: WSL2 Ubuntu + Claude Code 사용 중인 PC

---

## 0. 준비물 체크리스트

- [ ] PC (WSL2 Ubuntu, 절전 모드 꺼둘 수 있는 상태)
- [ ] 스마트폰 (Android 권장 — dev build 설치가 APK 한 방. iOS는 8단계 참고)
- [ ] 계정 4개: Expo(EAS), Google AI Studio, Cloudflare, Tailscale
- [ ] Claude 모바일 앱 설치 + 로그인

---

## 1. PC 기본 도구

```bash
# Node 20 LTS 확인 (없으면 nvm으로 설치)
node -v   # v20.x 이상

# 전역 도구
npm i -g eas-cli wrangler

# 버전 확인
eas --version
wrangler --version
```

WSL2 주의: watchman, Android SDK, Java는 **설치하지 않는다.** 네이티브 빌드는 전부 EAS 클라우드에서 수행하므로 로컬 빌드 환경이 필요 없다. 이게 이 구성의 핵심 단순화.

## 2. 계정 셋업

### 2-1. Expo / EAS

1. https://expo.dev 가입
2. `eas login` 으로 PC에서 로그인
3. 무료 플랜으로 충분 (월 빌드 횟수 제한 있음 — dev build는 초기 1회 + 네이티브 모듈 추가 시에만 재빌드)

### 2-2. Google AI Studio (Gemini 무료 티어)

1. https://aistudio.google.com 접속 → API 키 발급 (신용카드 불필요)
2. 키를 안전한 곳에 보관 — **앱 코드에 절대 넣지 않는다.** Cloudflare 프록시의 secret으로만 사용
3. 무료 티어 전제: 입력이 학습에 사용될 수 있음, 쿼터 변동 가능 (스펙 10장에 기록된 인지된 리스크)

### 2-3. Cloudflare Workers

1. https://dash.cloudflare.com 가입 (무료 플랜)
2. `wrangler login` 으로 PC 연동
3. 프록시 코드는 개발 지시서 M4에서 Claude Code가 작성. 여기서는 로그인까지만

## 4. Claude Code Remote Control 설정

> **WSL2 참고**: Remote Control은 공식적으로 WSL 미지원이 아니다 (아웃바운드 HTTPS 폴링 구조라 WSL NAT과 원리상 무관. WSL 미지원이 명시된 건 Claude in Chrome). 다만 WSL2에서 장수명 연결이 불안정하다는 리포트가 있고, 네트워크 10분 단절 시 세션이 종료되는 공식 제한이 있으므로 **아래 4-0 검증을 먼저 통과시킬 것.**

### 4-0. 사전 검증 (5분)

> ⚠️ **혼동 주의**: Claude Cowork/데스크톱 앱(Windows)에서 WSL 폴더를 여는 방식이 아니다 — 그쪽은 UNC 경로(`\\wsl.localhost\...`) 미지원으로 막힌다. Remote Control은 **WSL 터미널 안에서 claude를 실행**하고 폰이 그 세션에 접속하는 구조라 UNC가 개입할 지점이 없다. 프로젝트를 Windows 쪽(/mnt/c)으로 복사하지도 말 것 — Node/Expo 파일 I/O가 크게 느려지고 워처가 깨진다.

```bash
claude --version          # v2.1.51 이상 필수
cd /data/Github/expiry-tracker
claude remote-control     # 서버 모드 시작 → 스페이스바로 QR 표시
```

폰의 Claude 앱으로 QR 스캔 → 연결 → 메시지 왕복 확인. **10분쯤 방치 후에도 연결이 살아있으면 합격.**
끊김이 반복되면 `.wslconfig`에 `[wsl2] networkingMode=mirrored` 적용 후 재시도 (일부 환경에서 VS Code WSL 연결과 충돌 보고 있음 — 적용 전 상태 기억해둘 것). 그래도 불안정하면 플랜 B로 전환.

### 4-1. 정상 동작 시 (플랜 A)

1. `/config` 에서 **푸시 알림 활성화** ("Claude가 결정할 때 푸시")
2. 평소엔 `claude --remote-control "expiry-tracker"` 로 대화형+원격 겸용 세션 사용
3. 폰 Claude 앱 세션 목록에서 초록 점 세션 선택으로도 접속 가능

운영 메모:
- 세션은 PC에서 돌고 폰은 리모컨. PC 절전 후 깨어나면 자동 재연결 (단, 10분 이상 단절 시 종료 → SSH로 재시작)
- 대화형 세션당 원격 연결 1개
- Android 배터리 최적화에서 Claude 앱 제외, iOS는 집중 모드가 푸시를 막을 수 있음

### 4-2. 플랜 B — Remote Control이 불안정할 때

SSH(5장)를 백업이 아닌 **주 채널**로 승격한다. 이 구성만으로도 모바일 루프는 성립한다:

1. 폰 Termius → Tailscale SSH → `tmux attach -t dev` 에서 claude를 직접 대화형으로 조작
2. 푸시 알림 대체: Claude Code **Stop hook**에 텔레그램 봇 전송 스크립트 연결 (기존 봇 인프라 재사용) — "작업 완료/입력 대기" 알림 수신
3. Expo 핫리로드 확인 루프(6장)는 Remote Control 여부와 무관하게 동일하게 동작

플랜 B의 손해는 채팅 UI 대신 터미널 UI라는 것뿐이며, 기능적 손실은 없다.

## 5. Tailscale + SSH (백업 수단)

Remote Control은 "돌고 있는 세션 이어받기"라서, 세션이 죽으면 폰에서 새로 띄울 수단이 필요하다.

1. PC와 폰에 Tailscale 설치, 같은 계정으로 로그인
2. 폰에 Termius(또는 임의 SSH 앱) 설치 → Tailscale IP로 PC SSH 등록
3. 폰에서 SSH 접속 → `tmux` 안에서 `claude` 재시작 / `npx expo start --tunnel` 재기동 가능하면 합격

tmux 사용을 권장: SSH가 끊겨도 세션 유지.

```bash
tmux new -s dev      # 개발 세션
tmux new -s expo     # expo 서버 세션
```

## 6. Expo 개발 서버 + 폰 연결 (프로젝트 생성 후)

개발 지시서 M0에서 프로젝트가 생성된 뒤 수행:

```bash
cd /data/Github/expiry-tracker/app
npx expo start --tunnel
```

- **반드시 `--tunnel`**: WSL2의 네트워크 격리 때문에 LAN 모드는 폰에서 접속이 안 되는 경우가 많다. 터널은 이를 우회
- M3에서 ML Kit(네이티브 모듈) 도입 전까지는 Expo Go 앱으로 QR 스캔 접속 가능
- ML Kit 도입 후에는 dev build 필수 (아래 7단계)

## 7. Development Build (M3 시점에 1회)

```bash
eas build --profile development --platform android
```

- 빌드 완료되면 EAS가 주는 링크/QR로 폰에서 APK 설치
- 이후 JS 수정은 전부 핫리로드. **네이티브 모듈을 새로 추가할 때만 재빌드**
- 빌드 프로필은 개발 지시서 M0에서 Claude Code가 eas.json에 구성

## 8. (선택) iOS인 경우

- dev build 설치에 Apple Developer 계정 필요 (무료 계정은 7일마다 재서명, 유료 $99/년이면 제약 없음)
- 절차가 길어 **v1 개발은 Android 폰으로 진행하고 iOS는 배포 단계에서 대응**하는 것을 권장
